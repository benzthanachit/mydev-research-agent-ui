# 🐾 Meow-nuscript Foundry (โรงหล่อต้นฉบับแมวเหมียว)

**Meow-nuscript Foundry** คือเว็บแอปพลิเคชันระบบ **Multi-Agent AI** ในสไตล์ย้อนยุค **90s Retro 8-bit RPG** (ธีมออฟฟิศแมวสุดน่ารัก 🐱) ที่พัฒนาขึ้นโดยเฉพาะเพื่อช่วยเหลือและอำนวยความสะดวกแก่นักวิจัยในการเขียนและตรวจทานบทความวิจัยทางวิชาการ (Academic Manuscripts) ตามมาตรฐานของวารสารวิชาการระดับ **Scopus Q3 และ Q4** 

ระบบนี้ดำเนินงานด้วยการแบ่งขั้นตอนเป็นรายบทอย่างเคร่งครัด (**Chapter-by-Chapter Workflow**) พร้อมระบบอนุมัติโดยมนุษย์ (**Human-in-the-loop**) เพื่อประสิทธิภาพในการควบคุมเนื้อหาสูงสุด

---

## 🎮 บทบาทของตัวละครแมวออฟฟิศ (4 Cat Agents & Siamese Mascot)

1.  **แมววิเชียรมาศ (Siamese Cat - UI Mascot):** ทำหน้าที่เป็นพนักงานนำส่งข้อมูลหลัก เดินผ่านหน้าจอพร้อมอัญเชิญป๊อปอัปแจ้งเตือนเมื่อเกิดสถานะสำคัญในระบบ
2.  **Project Meow-nager (Agent 1 - ผู้จัดการสุดสมาร์ท 👓):** ทำหน้าที่สรุปความเห็นของผู้ประเมินเป็นหัวข้อกระชับ คอยประสานงาน และรอรับคำแนะนำเพิ่มเติมจากนักวิจัยก่อนดำเนินการต่อ
3.  **The Scribe Cat (Agent 2 - นักเขียนมือทอง ✍️):** ทำหน้าที่ดึงข้อมูลเชิงเทคนิค อัลกอริทึม หรือสมการที่กำหนด มาร่างเนื้อหารายละเอียดวิทยานิพนธ์อย่างเป็นทางการและถูกต้องตามหลักวิชาการ
4.  **Grumpy Reviewer (Agent 3 - ผู้ประเมินสุดเฮี้ยบ 🎓):** ทำหน้าที่ตรวจประเมินตามมาตรฐาน Scopus Q3/Q4 โดยเน้นที่ระเบียบวิธีวิจัยท### 3. การตั้งค่า NotebookLM (คลังข้อมูลวิจัย RAG สำหรับทำ RAG ความมั่นคงสูง)
NotebookLM ของ Google เป็นคลังจัดเก็บไฟล์วิจัยสำหรับทำ RAG ที่ยอดเยี่ยม เพื่อให้ระบบเหมียวประสานงานซิงก์บทวิจัยที่เขียนเสร็จเข้าสู่ NotebookLM ได้โดยตรง คุณสามารถเชื่อมต่อผ่าน **Model Context Protocol (MCP)** ได้ด้วยเซิร์ฟเวอร์เปิดของชุมชน **[PleasePrompto/notebooklm-mcp](https://github.com/PleasePrompto/notebooklm-mcp)**:

#### ⚡️ วิธีติดตั้งและใช้งานแบบเชื่อมตรง (Direct MCP Integration)
แอปพลิเคชัน Meow-nuscript Foundry ติดตั้งโมดูล **Stdio MCP Client** ในตัวเอง ทำให้ระบบหลังบ้าน (Node.js backend) สามารถรันและติดต่อกับ `notebooklm-mcp` ผ่านโปรโตคอล JSON-RPC ได้ในทันทีโดยไม่ต้องผ่านโปรแกรมภายนอกอื่นใด!

1. **การลงชื่อเข้าใช้งานแอปพลิเคชัน (Google Authentication):**
   * ไปที่แท็บ **Cognitive Settings [4]** บนเว็บเบราว์เซอร์ของแอปเรา
   * ปรับตัวเลือก **NOTEBOOKLM CONNECTION TYPE** ให้เป็น **`Direct Local MCP Server (PleasePrompto/notebooklm-mcp)`**
   * ระบบจะทำการตรวจสอบสถานะการเชื่อมต่อทันที หากขึ้นสถานะเป็น `Requires Auth 🟡` หรือ `MCP Offline 🔴` ให้กดปุ่ม **`⚡️ RUN GOOGLE AUTH (setup_auth)`**
   * หน้าต่างเบราว์เซอร์ Chromium ของเซิร์ฟเวอร์ย่อยจะเปิดขึ้นมา ให้คุณกรอกบัญชีและรหัสผ่าน Google ของคุณด้วยตนเองเพื่อล็อกอินเข้าสู่ NotebookLM อย่างปลอดภัย (ทำเพียงครั้งแรกครั้งเดียว) บราวเซอร์จะจัดเก็บคุกกี้เซสชันอย่างปลอดภัยภายในเครื่องของคุณและปิดตัวลงเมื่อเสร็จสิ้น
2. **การกรอก Notebook ID (ทางเลือก):**
   * ในช่อง **GOOGLE NOTEBOOK ID OR URL** คุณสามารถคัดลอกรหัสสมุดโน้ตวิจัยของคุณในหน้า NotebookLM (เช่น ส่วนรหัสท้าย URL หลัง `/notebook/`) มาป้อนไว้ได้ เพื่อให้ระบบอัปโหลดบทความเข้าสู่สมุดเล่มนั้นโดยเฉพาะ
3. **การทำงานร่วมกันเมื่อกดล็อกบทความ (Auto-Ingestion):**
   * ทุกครั้งที่คุณกดปุ่ม **🔒 LOCK & SAVE CHAPTER** ระบบจะสั่งการเรียกใช้คำสั่ง `add_source` ในรูปแบบ `type: "text"`
   * ตัวระบบจะนำเนื้อหาร่างบทความวิจัยที่ได้รับการประเมินผ่านแล้ว ซิงก์ยิงตรงเข้าสู่ Google NotebookLM ของคุณทันทีโดยไม่มีการหลุดรั่วหรือบันทึกรหัสผ่านของคุณใดๆ ทั้งสิ้น!

#### 🛠️ การตั้งค่าตัวแปรสภาพแวดล้อม (Environment Variables)
หากเซิร์ฟเวอร์ทำงานติดขัด มีปัญหากับเวอร์ชัน Chrome ในเครื่อง หรือต้องการปรับเปลี่ยนความเร็วในการป้อนข้อมูลวิจัย (Stealth Settings) คุณสามารถระบุตัวแปรสภาพแวดล้อมเหล่านี้ในไฟล์ `.env.local` ได้โดยตรงก่อนรันระบบ:

| ตัวแปรสภาพแวดล้อม | ค่าที่ใช้ได้ | ค่าเริ่มต้น | วัตถุประสงค์ในการใช้งาน |
|---|---|---|---|
| `BROWSER_CHANNEL` | `chrome` \| `chromium` | `chrome` | ในบาง OS (เช่น macOS Tahoe/Windows 11) โครมหลักอาจมีปัญหาล็อก Singleton ให้ปรับเป็น **`chromium`** เพื่อใช้ตัวรันจำลองที่แถมมากับ Patchright |
| `HEADLESS` | `true` \| `false` | `true` | ตั้งค่าเป็น `false` เพื่อเปิดดูภาพการทำงานของเบราว์เซอร์ในเบื้องหลังขณะอัปโหลดข้อมูล RAG |
| `NOTEBOOK_PROFILE_STRATEGY` | `auto` \| `single` \| `isolated` | `auto` | หากเปิด Chrome ค้างไว้ในเครื่องแล้วเจอปัญหาแย่งโปรไฟล์กัน ให้ปรับเป็น **`isolated`** เพื่อแยกโปรไฟล์อิสระ |
| `STEALTH_HUMAN_TYPING` | `true` \| `false` | `true` | จำลองจังหวะการพิมพ์เหมือนมนุษย์เพื่อไม่ให้ระบบ Google ตรวจจับ บล็อก หรือมองเป็นบอท |
| `TYPING_WPM_MIN` / `MAX` | ตัวเลขอัตราคำต่อนาที | `160` / `240` | ปรับความเร็วในการร่างอัปโหลดข้อมูล (หากต้องการความเร็วสูงขึ้น เช่น `400` / `600`) |

### 2. การตั้งค่า Obsidian Working Memory (ความจำระยะสั้น)
ระบบจะทำการบันทึก **"Micro-Facts"** และ **"Decision Logs"** เพื่อใช้เป็นบริบทในการเขียนบทถัดไปโดยไม่ทำให้ Context Window ของบอทล้น
*   **หากมี Obsidian ในเครื่อง:** เข้าไปที่แท็บ **Cognitive Settings [4]** และใส่ที่อยู่โฟลเดอร์จริงของ Obsidian Vault ลงในช่อง (เช่น `/Users/username/Documents/MyResearchVault`)
*   **หากไม่มี Obsidian:** ปล่อยว่างไว้ ระบบจะจำลองโฟลเดอร์เก็บข้อมูลชื่อ `obsidian-vault` ขึ้นมาที่โฟลเดอร์หลักของโปรเจกต์โดยอัตโนมัติ ซึ่งคุณสามารถเข้าตรวจดูไฟล์ `.md` ได้โดยตรงในโปรเจกต์นี้!

### 3. การตั้งค่า NotebookLM (คลังข้อมูลวิจัย RAG)
NotebookLM ของ Google เป็นคลังจัดเก็บไฟล์วิจัยสำหรับทำ RAG ที่ยอดเยี่ยม เพื่อให้ระบบเหมียวประสานงานซิงก์บทวิจัยที่เขียนเสร็จเข้าสู่ NotebookLM ได้โดยตรง คุณสามารถเชื่อมต่อผ่าน **Model Context Protocol (MCP)** ได้ด้วยเซิร์ฟเวอร์เปิดของชุมชน **[PleasePrompto/notebooklm-mcp](https://github.com/PleasePrompto/notebooklm-mcp)**:

#### ⚡️ วิธีติดตั้งและใช้งานผ่าน MCP Server (แนะนำสูงสุดเพื่อความปลอดภัยและการซิงก์อัตโนมัติ)
ปลั๊กอินนี้ทำงานผ่าน Browser Automation (Patchright) ในเครื่องของคุณ ทำให้ AI Agent สามารถเปิดเว็บเบราว์เซอร์ ล็อกอินด้วยบัญชี Google ของคุณอย่างปลอดภัย และช่วยจัดการบทความใน NotebookLM ได้โดยตรง!

1. **ติดตั้งเซิร์ฟเวอร์ลงในระบบของคุณ:**
   ในระบบ MCP Client ที่คุณใช้รัน (เช่น Claude Desktop, Cursor หรือ Claude Code) ให้เพิ่มการตั้งค่าเซิร์ฟเวอร์ในลักษณะนี้:
   ```json
   "mcpServers": {
     "notebooklm": {
       "command": "npx",
       "args": ["-y", "notebooklm-mcp@latest"]
     }
   }
   ```
2. **การเข้าสู่ระบบแบบปลอดภัย (Authentication):**
   * หลังจากเพิ่มบอทแล้ว ให้สั่งบอทในช่องแชทว่า *"เข้าสู่ระบบ NotebookLM ให้หน่อย"* หรือ *"Log me in to NotebookLM"*
   * หน้าต่างเบราว์เซอร์ Chromium จะเปิดขึ้นมาในเครื่องของคุณ ให้คุณกรอกบัญชีและรหัสผ่าน Google ของคุณด้วยตัวเอง บราวเซอร์จะจำเซสชันนี้ไว้แบบปลอดภัยโดยไม่ต้องบันทึกรหัสผ่านลงในโค้ดใดๆ
3. **การทำงานร่วมกับ Meow-nuscript Foundry:**
   * ทุกครั้งที่คุณกดปุ่ม **🔒 LOCK & SAVE** บนระบบ Meow-nuscript Foundry ไฟล์บทความวิจัยที่ได้รับการตรวจผ่านจะบันทึกเป็นไฟล์ Markdown (.md) ไว้ที่โฟลเดอร์ **`notebooklm-cold-storage`** ในโปรเจกต์
   * คุณสามารถสั่งผู้ช่วย AI ของคุณ (ที่เชื่อมโยงกับ MCP Server นี้อยู่) ได้ทันที เช่น:
     > *"ช่วยใช้เครื่องมือ notebooklm_add_source เพื่อนำไฟล์บทความใหม่ในโฟลเดอร์ notebooklm-cold-storage เข้าสู่สมุดโน้ตวิจัยของฉันใน NotebookLM ให้หน่อยนะเหมียว"*
   * AI Agent จะทำการนำเข้าบทความเข้าสู่คลัง Google NotebookLM ในพริบตาเพื่อใช้ในการทำ RAG ต่อไป!

#### 🔗 วิธีที่ 4: เชื่อมต่อผ่าน Webhook ปลายทาง (ทางเลือกเพิ่มเติม)
* ป้อน URL Webhook ขาออกในหน้า Settings เพื่อส่งบทความวิจัยที่ถูกล็อกในระบบยิงไปยังบริการอย่าง Make.com หรือ Zapier เพื่อให้เซฟลง Google Drive แล้วซิงก์กับ NotebookLM อีกทีหนึ่ง
* หากไม่ระบุทั้งสองอย่าง ระบบจะบันทึกเก็บเป็นไฟล์ `.md` ออฟไลน์ไว้ที่โฟลเดอร์ `/notebooklm-cold-storage` เพื่อให้คุณคัดลอกไปอัปโหลดขึ้นเว็บ NotebookLM แบบแมนวลได้ฟรีตามสะดวกครับ!

## 🚀 วิธีการรันแอปพลิเคชัน (How to Run)

หลังจากทำตามขั้นตอนการตั้งค่าเรียบร้อยแล้ว ให้เปิด Terminal ในโฟลเดอร์หลักของโปรเจกต์ แล้วทำตามขั้นตอนดังนี้:

### 1. ติดตั้ง Dependencies
```bash
npm install
```

### 2. รัน Developer Server (เซิร์ฟเวอร์ทดสอบ)
```bash
npm run dev
```

หลังจากนั้น เปิดเว็บเบราว์เซอร์ไปที่ [http://localhost:3000](http://localhost:3000) เพื่อเริ่มต้นงานเขียนร่วมกับแก๊งออฟฟิศแมวเหมียว!

## 🔄 ขั้นตอนการดำเนินงานเขียน (State Machine Workflow)

1.  **เตรียมการและป้อนเป้าหมาย (Stage Selection):** ป้อนหัวข้อโครงร่าง ระเบียบวิธี และการทำงานของสมการในแท็บ **Workbench [1]**
2.  **ร่างข้อมูล (Drafting State):** กดปุ่ม **"RUN SCRIBE CAT DRAFT"** บรรดาแมวนักเขียนจะเริ่มดึงข้อมูลจากความจำมาเขียน และคุณสามารถกดดูฉบับร่างได้ทันทีที่แท็บ **Manuscript Draft [2]** (สามารถแก้ไขข้อความได้โดยตรงในฐานะมนุษย์ผู้ตรวจสอบ)
3.  **ประเมินผลสุดโหด (Review State):** กดส่งให้ตรวจประเมิน หากเกิด `[FAIL]` จาก Grumpy Reviewer ป๊อปอัปออฟฟิศจะติดกรอบสีแดงพร้อมรายการจุดบกพร่องวิชาการที่ต้องแก้ ให้ปรับค่าแล้วกดเขียนใหม่ หากตรวจผ่าน (`[PASS]`) จะเปิดทางสู่ระบบบรรณารักษ์
4.  **ตรวจสอบการอ้างอิง (Citation Check):** รัน Librarian Cat เพื่อเช็กรูปแบบฟอร์แมตอ้างอิง ข้อมูลจะปรากฏขึ้นบนม้วนกระดาษโบราณจำลอง
5.  **ล็อกล็อกความสำเร็จ (Save State):** เมื่อทุกขั้นตอนเรียบร้อย กดปุ่ม **🔒 LOCK & SAVE** เพื่อเก็บข้อมูลลงคลังความจำ Obsidian และแช่แข็งผลลัพธ์ลง NotebookLM ก่อนเริ่มบทถัดไป!

## 💻 เทคโนโลยีที่ใช้หลัก (Core Stack)
*   **Frontend:** Next.js 16 (React 19), Tailwind CSS v4 
*   **Styling (ธีมย้อนยุค):** Google Fonts (Press Start 2P, VT323) ร่วมกับการจัดโครงสร้าง HTML `<img>` tags ที่ประมวลผลพิกเซลพิกเซลดึงเอาความคมชัดดั้งเดิมของภาพ RPG
